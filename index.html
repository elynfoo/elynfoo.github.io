3 Build

Containerising the Application

Every app I build gets containerised with Docker — ensuring it runs identically in development, testing, and production.

The Problem

"Works on my machine" is not a deployment strategy. Without containers, environment drift between dev and production caused silent failures that were hard to diagnose.

What I Built

Dockerfiles for each Flask application, multi-container setups with Docker Compose for local development, and image publishing to Docker Hub as part of the CI pipeline.

Impact

Any team member can pull the image and run an identical environment in seconds. No setup docs, no version mismatches, no surprises.

5 Release

Zero-Touch Deployment Pipeline

⭐ Featured Project: Containerised Flask Portfolio Pipeline

Built a full CI/CD pipeline in Azure DevOps that handles the complete release lifecycle automatically.

The Challenge

Configuring pipeline triggers, securely injecting Docker Hub credentials as pipeline variables, and ensuring the build only proceeds when the image was successfully pushed — all without hardcoding any secrets.

The Pipeline

Commit to Azure Repos → Azure DevOps trigger fires → Docker image built → Image pushed to Docker Hub → Kubernetes manifest applied → App live. 15 manual steps reduced to zero.

Impact

Full audit trail, consistent builds, and zero deployment anxiety. This mirrors exactly how production DevOps teams operate.

7 Operate

Infrastructure as Code

Infrastructure shouldn't be clicked into existence — it should be written, versioned, and repeatable. That's the philosophy behind my Terraform and Ansible work.

⭐ Featured Project: Terraform + Ansible Azure VM Deployment

Provisioned an Azure Ubuntu VM from scratch and automatically configured it to run a Flask application — entirely through code.

The Challenge

Chaining two tools with different responsibilities: Terraform for provisioning the VM (the "what exists") and Ansible for configuring it (the "what runs on it"). Getting the hand-off right — passing the VM's IP from Terraform output to Ansible's inventory — required careful orchestration.

The Solution

Terraform creates the Azure VM and outputs its public IP. An Ansible playbook picks up that IP, installs Python and Flask, copies the app, and starts the service. Fully automated, fully repeatable — destroy and re-run in minutes.

Impact

Any environment can be reproduced on demand. No snowflake servers, no undocumented manual steps — just code and a single command.

8 Monitor

Seeing What's Actually Happening

The pipeline isn't complete without visibility. You can't improve what you can't see.

⭐ Featured Project: Web Network Scanner Dashboard

Built a browser-accessible network monitoring dashboard for Linux — turning raw Nmap output into a live, human-readable view of every active device on the network.

The Problem

Network monitoring tools are either enterprise-priced or CLI-only. I wanted something lightweight that any team member could open in a browser — no install, no login.

The Solution

A Bash script schedules Nmap scans, PHP parses and formats the output, and Apache serves the results as a live-refreshing dashboard. Open a browser on any device on the network and the data is right there.

What I Learned

The best monitoring tools are the ones people actually open. Simplicity is a feature — not a shortcut. This project deepened my understanding of Linux process scheduling, web server configuration, and network fundamentals.
